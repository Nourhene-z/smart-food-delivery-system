# Smart Food Delivery System - Copilot Instructions

This file provides context and guidelines for GitHub Copilot and other AI assistants working with this codebase.

## Project Overview

**Smart Food Delivery System** is a production-quality Spring Boot 3.5.0 application demonstrating advanced software design patterns and resilience mechanisms.

- **Primary Language**: Java 21
- **Framework**: Spring Boot 3.5.0
- **Architecture**: Layered (Controller → Service → Repository)
- **Database**: MySQL 8.0
- **Cache**: Redis 7.0
- **Patterns**: Circuit Breaker, Retry, Cache, Strategy

## Coding Standards

### Java Conventions
- Use Java 21 features (records, switch expressions where appropriate)
- Follow Google Java Style Guide
- 4-space indentation, max 100 character lines
- PascalCase for classes, camelCase for methods
- UPPER_SNAKE_CASE for constants

### Spring Boot Standards
- Use component scanning and dependency injection
- Apply `@Transactional` to service methods that modify data
- Use `@RequiredArgsConstructor` with Lombok for constructor injection
- Apply `@Slf4j` from Lombok for logging
- Create DTOs for API contracts, separate from entities

### Design Patterns
1. **DTO Pattern**: Create separate DTOs for requests/responses
2. **Repository Pattern**: Use Spring Data JPA repositories
3. **Service Layer**: Encapsulate business logic
4. **Exception Handling**: Use global exception handler (`GlobalExceptionHandler.java`)
5. **Layered Architecture**: Separate concerns into distinct layers

## Code Generation Guidelines

### Entity Classes
When generating entities:
- Use `@Entity` and `@Table` annotations
- Use `@Data`, `@Builder`, `@NoArgsConstructor`, `@AllArgsConstructor` from Lombok
- Include `@PrePersist` and `@PreUpdate` hooks for audit fields
- Use appropriate `@Enumerated(EnumType.STRING)` for enums
- Add validation annotations: `@NotNull`, `@NotBlank`, `@Email`, etc.

Example:
```java
@Entity
@Table(name = "orders")
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class Order {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @NotNull
    private Long customerId;
    
    @Enumerated(EnumType.STRING)
    private OrderStatus status;
    
    @PrePersist
    protected void onCreate() {
        if (createdAt == null) {
            createdAt = LocalDateTime.now();
        }
    }
}
```

### Service Classes
When generating services:
- Use `@Service` and `@RequiredArgsConstructor` from Lombok
- Inject dependencies via constructor
- Apply `@Transactional` for methods that modify data
- Use `@Cacheable` for read-heavy operations
- Include proper logging with `@Slf4j`
- Throw `ResourceNotFoundException` for 404 scenarios
- Return DTOs from public methods, not entities

Example:
```java
@Service
@RequiredArgsConstructor
@Slf4j
public class OrderService {
    private final OrderRepository orderRepository;
    private final CustomerRepository customerRepository;
    
    @Transactional
    public OrderDto createOrder(CreateOrderRequest request) {
        var customer = customerRepository.findById(request.getCustomerId())
            .orElseThrow(() -> new ResourceNotFoundException("Customer not found"));
        
        var order = Order.builder()
            .customerId(request.getCustomerId())
            .status(OrderStatus.PENDING)
            .build();
        
        orderRepository.save(order);
        log.info("Order created: {}", order.getId());
        return convertToDto(order);
    }
}
```

### Controller Classes
When generating controllers:
- Use `@RestController` and `@RequestMapping` annotations
- Inject service via `@RequiredArgsConstructor`
- Return `ApiResponse<T>` wrapper for all endpoints
- Include proper HTTP status codes (201 for POST, 200 for GET, etc.)
- Add input validation with `@Valid` annotation
- Document endpoints with JavaDoc

Example:
```java
@RestController
@RequestMapping("/api/orders")
@RequiredArgsConstructor
public class OrderController {
    private final OrderService orderService;
    
    @PostMapping
    public ResponseEntity<ApiResponse<OrderDto>> createOrder(
            @Valid @RequestBody CreateOrderRequest request) {
        var orderDto = orderService.createOrder(request);
        return ResponseEntity.status(HttpStatus.CREATED)
            .body(ApiResponse.success(orderDto, "Order created successfully"));
    }
}
```

## Design Pattern Implementation

### Circuit Breaker Usage
- Use `@CircuitBreaker` annotation on methods calling external services
- Always provide `fallbackMethod` parameter
- Combine with `@Retry` for additional resilience
- Log circuit breaker state changes

```java
@CircuitBreaker(name = "gpsServiceCircuitBreaker", fallbackMethod = "getDeliveryFallback")
@Retry(name = "deliveryTrackingRetry")
public DeliveryDto getDeliveryWithLocation(Long deliveryId) {
    // External call
}

public DeliveryDto getDeliveryFallback(Long deliveryId, Exception ex) {
    // Fallback logic
    log.warn("Circuit breaker fallback for delivery {}", deliveryId);
    return getLastKnownDelivery(deliveryId);
}
```

### Cache Pattern Usage
- Use `@Cacheable` for read operations with `unless` condition
- Always provide cache name: `value="cacheName"`
- Use `key` parameter for cache key customization
- Add TTL configuration in application.yml

```java
@Cacheable(value = "restaurants", unless = "#result.isEmpty()")
public List<RestaurantDto> getAllRestaurants() {
    return restaurantRepository.findByIsActiveTrue().stream()
        .map(this::convertToDto)
        .collect(Collectors.toList());
}
```

### Strategy Pattern Usage
- Create interface for strategy contract
- Implement concrete strategies as `@Component` beans
- Use factory for strategy selection
- Allow runtime strategy switching

```java
public interface PaymentStrategy {
    boolean processPayment(Long orderId, Double amount);
    String getPaymentMethodName();
}

@Component
public class CreditCardPayment implements PaymentStrategy {
    @Override
    public boolean processPayment(Long orderId, Double amount) {
        // Implementation
    }
}
```

## Testing Guidelines

### Unit Tests
- Use `@ExtendWith(MockitoExtension.class)`
- Mock external dependencies
- Test both success and failure scenarios
- Verify service.save() and repository methods called

```java
@ExtendWith(MockitoExtension.class)
class OrderServiceTest {
    @Mock
    private OrderRepository orderRepository;
    
    @InjectMocks
    private OrderService orderService;
    
    @Test
    void testCreateOrder_Success() {
        var request = new CreateOrderRequest(1L, 1L, 50.0, "Address", "CREDIT_CARD");
        when(orderRepository.save(any())).thenReturn(/*mocked order*/);
        
        var result = orderService.createOrder(request);
        
        assertNotNull(result);
        verify(orderRepository).save(any());
    }
}
```

## Common Issues & Solutions

### Issue: Duplicate Entity IDs
- Solution: Ensure `@GeneratedValue(strategy = GenerationType.IDENTITY)` is applied

### Issue: LazyInitializationException
- Solution: Use eager loading with `@Query` or service fetching logic

### Issue: Stale Cache
- Solution: Implement cache invalidation strategies or set appropriate TTL

### Issue: Circuit Breaker Not Triggering
- Solution: Verify `minimumNumberOfCalls` and `failureRateThreshold` configuration

## Performance Considerations

When generating code:
1. **Database Queries**: Use pagination for large result sets
2. **Caching**: Cache expensive queries and external service calls
3. **Async Operations**: Use async methods for I/O operations (if needed)
4. **Index Strategy**: Index frequently queried columns
5. **Connection Pooling**: Use HikariCP with appropriate pool size

## Security Considerations

1. **Input Validation**: Always validate input with `@Valid` and `@NotNull`
2. **SQL Injection**: Use JPA/Hibernate with parameterized queries (not string concatenation)
3. **Error Messages**: Don't expose sensitive information in error responses
4. **Logging**: Never log passwords, API keys, or sensitive data
5. **Secrets**: Use environment variables or external secrets management
